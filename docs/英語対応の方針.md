# 英語対応の方針（2026-11-10 決定）

## 決めたこと

- 言語は日本語のほかに **英語だけ** を足す。中国語・韓国語などは、英語が済んでから考える。
- 審査中のビルド 13（2.0.0）には入れない。ブランチ `l10n-english`（`fix-permission-prompts` から分岐）で作り、2.0.0 の審査が通って公開したあとに **2.0.1** として出す。
- 対象は、日本に住む外国の方や旅行者。気象庁のデータは日本だけが対象なので、海外の場所は見張れない（この制限は英語の文でも伝える）。
- 法律と規約の決まり（予報にあたる言い回しをしない、出典表記）は、英語でも同じように守る。出典は画面で「Source: Japan Meteorological Agency」、データの出典ページとストアページで「Source: Japan Meteorological Agency website (processed by the app)」とする。

## 手を入れる場所（調べた結果）

いまは `flutter_localizations` も `intl` も入っておらず、文言は日本語のまま 52 個のファイルに直接書いてある（コメントを含めて約 390 行）。

- アプリの画面の文言: home、plus、settings、intro、finder、welcome など。`lib/screens` と `lib/widgets`。
- 画面以外にある文言: `lib/models`（sky_cloud、sky_now、prefectures）、`lib/services`（member_service、cloud_notifications、plus_service、report_service）、`lib/utils`。
- 場所の名前を調べる処理（`current_place.dart`）は、日本語に固定してある。英語のときの表記をどうするかを決める。
- 都道府県（`prefectures.dart`）の英語名。
- 通知の文言: サーバー（`functions/index.js`、`functions/constants.js`）が作っている。端末の言語をサーバーに保存し、言語ごとに文を作る。**Cloud Functions のデプロイが要るので、デプロイの前に必ず確認を取る**（関数名を指定して行う）。
- iOS のウィジェット（`ios/CloudWidget/CloudWidget.swift`）の文言と、iOS の言語設定（`Info.plist`、アプリ名）。
- App Store Connect: 英語の概要、プロモーション用テキスト、キーワード、スクリーンショット、アプリ内課金の表示名と説明。

## 進める順番

1. 文言の一覧を作る（日本語と英語の対応）。tsuchida さんに英語の文を見てもらう。
2. アプリの多言語化のしくみを入れる（`flutter_localizations` + `intl`、arb ファイル）。日本語の見え方が変わらないことを、既存のテストで確かめる。
3. 画面の文言を、一覧にしたがって置き換える。
4. 場所の名前と都道府県の英語表記。
5. iOS（ウィジェット、アプリ名、言語の宣言）。
6. 通知の文言（サーバー）。デプロイは確認を取ってから。
7. ストア用の英語の文章とスクリーンショット。
8. 英語の設定のシミュレーターで、全画面を確かめる。

## 決めたこと（2026-11-10 tsuchida さん）

- 英語のときのアプリ名は **Thunderhead Watch**（日本語のときは「入道雲サーチ」のまま。アプリ名の切り替えは iOS の InfoPlist.strings で行う）。
- 場所の名前は、英語の設定のとき **英語表記**（逆ジオコーディングを英語で呼ぶ）。
- 「入道雲」は英語で **thunderhead**。
