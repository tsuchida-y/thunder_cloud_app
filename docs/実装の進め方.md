# 実装の進め方

1ステップずつ、Claude Code に「ステップNをやって」と頼みます。各ステップの最後に、アプリを実際に動かして確認し、問題がなければ次へ進みます。仕様書の進め方 (試作〜11/15、サーバー作り直し〜12/31、画面づくり〜2/15、Plusと公開準備〜2/28) に合わせた順番です。

## ステップ0: 計画 (コードは変えない)

既存のコードを読み、仕様書・デザインとのちがいを洗い出す。消すもの (Open-Meteo、独自の発生判定、Google マップの背景、コミュニティ画面)、残して使い回すもの (Firebase の初期化、FCM、カメラ、写真の保存)、新しく作るものを分けて、ステップ1〜10をこのリポジトリ向けに具体化した計画を見せる。

## ステップ1: 気象庁ナウキャストの試作 (サーバー)

Cloud Functions に、気象庁ホームページの高解像度降水ナウキャストと雷ナウキャストを5分ごとに取得し、「強い雨の塊」や「雷のある場所」を雲の塊として取り出す処理を作る。最初の目安は、1時間に30mm以上の雨、または雷の活動度2以上。結果は Firestore に「いまある雲の一覧 (中心の緯度経度、強さ、見つけた時刻)」として保存する。前回の塊から15km以内なら同じ雲として追いかける。取得に失敗したときのログも入れる。まだ通知は送らない。

## ステップ2: 判定と通知の作り直し (サーバー)

既存の5分ごとの見張り (monitorThunderClouds など) を、ステップ1の雲の一覧を使う形に置き換える。ユーザーごとに方角・距離を計算し、範囲内 (無料30km / Plus 90km) の雲を判定する。通知のルール (1雲1回、30分間隔、1日3回、日没〜日の出は停止、開いて10分以内は送らない) を入れる。通知に「見えた」「見えなかった」のボタンを付け、押された結果を保存する。Open-Meteo と独自判定のコードを消す。

## ステップ3: テーマと共通部品 (アプリ)

色・フォント・グラデーション背景・カード・ボタンをまとめたテーマを作る。Google マップの背景をやめ、画面の行き来 (ホーム、方角ガイド、設定、記録) の土台を作る。中身は空でよい。

## ステップ4: ホーム

Main.html と Empty.html の通り。サーバーの雲の一覧から、一言の見出し、レーダー、雲の一覧、最後に空を見た時刻を出す。夜 (Night.html)、通信できないとき (Offline.html)、許可がないとき (NoPermission.html) の状態もここで作る。

## ステップ5: 方角ガイド

Finder.html、FinderAligned.html、Calibrate.html の通り。方位センサーで「右へ35°」を出し、ずれが10°以内で「この方向です」と振動。真後ろは「後ろを向いて」。見上げる高さはこぶしの数で出す。通知から開いたときは方角ガイドを直接開き、「見えた」「見えなかった」を聞く。

## ステップ6: はじめての起動と許可

Welcome.html (使用中の位置情報と通知だけ) と AlwaysAllow.html (最初の通知のあとに1回だけ「常に」をお願い)。iOS と Android それぞれの手順で確認する。

## ステップ7: 設定と場所の登録

Settings.html と Places.html。範囲 30km / 90km(Plus)、予告通知 (Plus)、通知しない時間 (初めは「なし」)、見張る場所 (無料は1か所、Plus は3か所まで)、データの出典ページ、利用規約、プライバシーポリシー。

## ステップ8: 記録

Record.html。見えた入道雲の一覧を出す。カメラ・写真・共有は v2.0 では作らない (2026-10-21 決定。コードとパッケージは削除済み)。

## ステップ9: Plus とウィジェット

RevenueCat で月額200円・年額1,200円・7日間無料を組み込み、Plus.html の画面を作る (無料期間後の値段と自動更新をボタンのそばに出す)。Plus で使える機能に鍵をかける。Widget.html のホーム画面ウィジェット (iOS / Android) を作る。

## ステップ10: 仕上げ

プライバシーポリシーを新しい位置情報の使い方と Plus に合わせて書き直す。既存の利用者へ、コミュニティを外したことと新しい使い方を知らせる。文言の最終確認 (独自の予想を表す言葉が残っていないか、出典表記)、ベータ配布の準備。
