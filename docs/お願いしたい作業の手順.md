# お願いしたい作業の手順

docs/残りの作業と確認事項.md の「2. tsuchida さんにお願いしたい作業」の、具体的なやり方です。
上から順にやるのがおすすめです（1 の実機での確認は、いつでも始められます）。
2026-10-22 から、まず iPhone だけを進めています。Android の部分（Android の実機、Google Play Console、RevenueCat の Google Play）は、あとでやるときに使ってください。
コンソールの画面のボタンの名前は、変わっていることがあります。見つからないときは、近い名前のものを探すか、Claude に画面の写真を見せてください。

このアプリの ID: iPhone・Android とも `com.tsuchida.thundercloud`（Apple のチーム ID は M72UA24TVV）

## 1. 実機での確認

### 1-1. 実機でアプリを動かす

iPhone の場合:
1. iPhone を Mac にケーブルでつなぎ、iPhone に出る「このコンピュータを信頼しますか」で「信頼」を押す。
2. iPhone の「設定 > プライバシーとセキュリティ > デベロッパモード」をオンにする（再起動を求められたら従う）。
3. ターミナルでリポジトリのフォルダに移り、`flutter devices` を実行する。iPhone の名前が出ればつながっている。
4. `flutter run -d "iPhoneの名前"` を実行する。初回はビルドに数分かかる。署名のエラーが出たら、Xcode で ios/Runner.xcworkspace を開き、Runner の「Signing & Capabilities」でチームを選んでから、もう一度実行する。

Android の場合:
1. Android の「設定 > デバイス情報」の「ビルド番号」を7回押して開発者向けオプションを出し、「USB デバッグ」をオンにする。
2. Mac にケーブルでつなぎ、Android に出る「USB デバッグを許可しますか」で許可する。
3. `flutter devices` で名前が出たら、`flutter run -d "Androidの名前"` を実行する。

夜でも雲の画面を試したいときは、最後に `--dart-define=FORCE_DAYTIME=true` を付ける（デバッグ版だけで効く）。

### 1-2. 確かめること

アプリを入れ直したら、はじめての起動の画面で「許可してはじめる」を押し、位置情報は「アプリの使用中は許可」、通知は「許可」を選ぶ。

- 方角ガイド: ホームに雲が出ているときに「雲の方角を調べる」を押し、体ごと回って「右へ ○°」の数字が減り、向きが合うと「この方向です」と出て振動するか。iPhone で方角の数字が出ない・動かないときは Claude に知らせる。
- 見張る場所: 設定 > 見張る場所 で地名（例「盛岡」）を入れて検索し、候補を押して名前を付けて登録できるか。「変更」から名前を変えたり消したりできるか。
- 設定: 通知のオン・オフや通知しない時間を変えたあと、Firebase コンソール（https://console.firebase.google.com/ → thunder-cloud-app-292e6 → Firestore Database → members）で自分のドキュメントの settings が変わるか。自分のドキュメントは、locationUpdatedAt が新しいものを探すと見つけやすい。
- 通信できないとき: 機内モードにしてアプリを開き、10秒ほどで「空の情報が受け取れません。」の画面に変わるか。
- 通知: 昼のあいだに、いまいる場所から30km以内に雲が出ると届く。届いたら、通知を押して方角ガイドが開くか、通知を長押しして「見えた」「見えなかった」を押せるか（押したあとアプリを開くと、記録の画面に出る）。最初の通知のあとにアプリを開くと「出かけた先の空も、見張りましょうか。」が1回出るか。
  - 近くに雲がなくて試せないときは、Claude に言ってください。tsuchida さんの分だけ一時的に Plus 扱いにして、雲が出ている場所を「見張る場所」に登録して試す方法があります。
- 「常に」: 上のお願いで「常に」にしたあと、1km以上移動して、Firestore の自分のドキュメントの locationSource が background に変わるか（Android は15分以上かかることがある）。
- ウィジェット（Android）: ホーム画面を長押し > ウィジェット > 入道雲サーチ から「入道雲（小）」「入道雲（中）」を置く。置くときに「ウィジェットで見る場所」の画面が出るので、場所を選ぶ。あとから変えるときは、ウィジェットを長押しして設定を開く。Plus でないので「Plus の機能です」と出れば正しい。

## 2. Plus の準備（App Store Connect、Google Play Console、RevenueCat）

### 2-1. 先に済ませておくこと

- App Store Connect の「契約／税金／口座情報」で、有料 App の契約（Paid Apps Agreement）と、口座・税金の情報を入れる。これがないと、課金のテストもできない。
- Google Play Console の「お支払いプロファイル」を作る（販売者のアカウント）。

### 2-2. App Store Connect（iPhone の商品）

1. https://appstoreconnect.apple.com/ で入道雲サーチを開き、「サブスクリプション」で「サブスクリプショングループ」を作る（名前は「入道雲サーチ Plus」など）。
2. グループの中に月額の商品を作る。
   - 参照名「Plus 月額」、製品 ID `plus_monthly`、期間 1か月、価格 200円
3. 「サブスクリプションのローカリゼーション」（日本語の表示名と説明。例「Plus（月額）」「90km先までの入道雲、見張る場所3か所、ウィジェット」）と、審査用のスクリーンショット（Plus の画面）を入れる。
4. 「お試しオファー（Introductory Offer）」で、「無料」「7日間」を作る。
4-2. 買い切りは、サブスクリプションではなく「App 内課金」のページで、種類「非消耗型（Non-Consumable）」で作る（2026-10-27 に年額をやめて買い切りにした）。
   - 参照名「Plus 買い切り」、製品 ID `plus_lifetime`、価格 1,600円
   - ローカリゼーション（例「Plus（買い切り）」と説明）と、審査用のスクリーンショットを入れる。買い切りには無料体験は付けられない。
5. 「ユーザとアクセス > 統合 > App 内課金」で「App 内課金キー」（.p8 のファイル）を作ってダウンロードする（RevenueCat に入れる）。キー ID と、ページの上に出る発行者 ID（Issuer ID）もメモする。

### 2-3. Google Play Console（Android の商品）

1. https://play.google.com/console/ で入道雲サーチを開き、次の2つを作る。
   - 「収益化 > 定期購入」で、商品 ID `plus_monthly`、名前「Plus（月額）」。基本プランを作り、自動更新、請求期間 1か月、価格 200円。
   - 「収益化 > アプリ内アイテム」で、商品 ID `plus_lifetime`、名前「Plus（買い切り）」、価格 1,600円（1回だけの購入）。
2. 月額の基本プランに「特典」を足し、対象を「新規のお客様」、フェーズを「無料試用期間 7日」にして有効にする。基本プランと特典の両方を「有効」にするのを忘れない。
3. Google Cloud で、RevenueCat 用のサービスアカウントを作り、JSON の鍵をダウンロードする。そのサービスアカウントを Play Console の「ユーザーと権限」に招待し、「財務データの閲覧」「注文と定期購入の管理」の権限を付ける。細かい手順は RevenueCat の案内（Google Play の Service Account credentials）に沿う。権限が効くまで最大36時間ほどかかることがある。
4. 「設定 > ライセンス テスト」に自分の Google アカウントを入れる（テストの購入でお金がかからないようにする）。

### 2-4. RevenueCat

tsuchida さんは、ほかのアプリで RevenueCat を使ったことがある（2026-10-29）。そのときのものは次のように使い回せる。
- RevenueCat のアカウントはそのまま使い、入道雲サーチ用に新しいプロジェクトを作る（ほかのアプリと売上や利用者が混ざらないように）。
- App 内課金キー（.p8）は開発者アカウントごとのものなので、前に作ったキーのファイルとキー ID が手元にあれば、新しく作らずにそれを入れてよい。ファイルをなくしていたら、2-2 の5で新しく作る（.p8 は作ったときに1回しかダウンロードできない）。
- サンドボックスのテスト用 Apple ID も、前に作ったものをそのまま使える。
- webhook の URL と合言葉、権利・Offering・API キーは、アプリごとに新しく作る。

1. https://app.revenuecat.com/ でアカウントとプロジェクト（名前「入道雲サーチ」）を作る。無料プランで始められる（売上が月2,500ドルまでは無料。最新の条件は RevenueCat の料金ページで確かめる）。
2. プロジェクトにアプリを2つ足す。
   - App Store: Bundle ID `com.tsuchida.thundercloud`、2-2 の5の App 内課金キー（.p8）、キー ID、発行者 ID を入れる。
   - Google Play: パッケージ名 `com.tsuchida.thundercloud`、2-3 の3のサービスアカウントの JSON を入れる。
3. 「Product catalog > Products」で、iPhone と Android の `plus_monthly`・`plus_lifetime` を読み込む（ストアから取り込むボタンがある）。
4. 「Entitlements」で ID `plus` の権利を作り、4つの商品をすべてつなぐ。アプリはこの `plus` という名前を見ている。
5. 「Offerings」で ID `default` の Offering を作り、「現在の Offering（current）」にする。中に2つのパッケージを足す。
   - 種類「Monthly」（`$rc_monthly`）に、iPhone と Android の `plus_monthly`
   - 種類「Lifetime」（`$rc_lifetime`）に、iPhone と Android の `plus_lifetime`
6. 「Project settings > API keys」で、iPhone 用（`appl_` で始まる）と Android 用（`goog_` で始まる）の公開用の SDK キーを Claude に教える。この2つは公開してよいキーなので、チャットに貼ってかまわない。
7. 「Integrations > Webhooks」で webhook を足す。
   - URL: `https://asia-northeast1-thunder-cloud-app-292e6.cloudfunctions.net/revenuecatWebhook`
   - Authorization header: ターミナルで `firebase functions:secrets:access REVENUECAT_WEBHOOK_AUTH` を実行して出る値（「Bearer 」から始まる）をそのまま貼る。この値は他の人に見せない。
   - 「Send test event」を押す。テストのイベントはサーバーが受け取って何もしない作りなので、成功と出ればつながっている。

### 2-5. お試しの購入

1. キーを Claude に教えたあと、`flutter run -d "端末の名前" --dart-define=REVENUECAT_IOS_KEY=（iPhone 用）--dart-define=REVENUECAT_ANDROID_KEY=（Android 用）` で動かす。
2. iPhone は「設定 > App Store > サンドボックスアカウント」に、App Store Connect の「ユーザとアクセス > サンドボックス」で作ったテスト用の Apple ID を入れておく。Android は 2-3 の4のライセンステスト用のアカウントで端末にログインしておく。
3. 設定 > Plus の帯から Plus の画面を開き、「7日間 無料で試す」で買う。サンドボックスでは時間が早く進む（1か月が数分）。
4. 買ったあと、Firestore の member_server で自分のドキュメントの isPlus が true になるか。解約して期限が来ると false に戻るか。範囲の 90km を選べるようになるか。

## 3. iOS のウィジェットを Xcode で足す

1. Apple Developer（https://developer.apple.com/account/ ）の「Identifiers」で、App Groups に `group.com.tsuchida.thundercloud` を作る。
2. Xcode で ios/Runner.xcworkspace を開く（.xcodeproj ではなく .xcworkspace）。
3. File > New > Target > Widget Extension を選ぶ。Product Name は `CloudWidget`、「Include Live Activity」と「Include Configuration App Intent」のチェックは外して、Finish。「Activate “CloudWidget” scheme?」と聞かれたら Cancel でよい。
4. 左の一覧にできた CloudWidget フォルダの中の Swift ファイル（CloudWidget.swift、CloudWidgetBundle.swift など）を消し（Move to Trash）、リポジトリの ios/CloudWidget/CloudWidget.swift を CloudWidget フォルダにドラッグして入れる。そのとき「Copy items if needed」は外し、「Add to targets」は CloudWidget だけにチェックする。
5. ターゲット CloudWidget の「General」で Minimum Deployments を iOS 17.0 にする。
6. ターゲット Runner と CloudWidget の両方で「Signing & Capabilities」を開き、「+ Capability」から App Groups を足して、`group.com.tsuchida.thundercloud` にチェックを入れる。チームも両方同じにする。
7. ターミナルで `flutter run -d "iPhoneの名前"` を実行し、アプリを一度開いてから、ホーム画面を長押し > 左上の「+」> 入道雲サーチ でウィジェットを置く。
   - 見る場所を変えるときは、置いたウィジェットを長押し >「ウィジェットを編集」>「場所」で、いま・家・学校などから選ぶ。
   - ウィジェットをタップして、その場所に切り替わったホームが開くか確かめる。
   - Plus でないと「Plus の機能です」と出る（それで正しい）。
8. うまくいかないときは、出たエラーの文を Claude に貼る。

## 4. 気象庁のデータが取れなくなったら、メールで知らせる

2026-10-23 に Claude が gcloud で作りました（アラート「気象庁のデータが取れない（入道雲サーチ）」、宛先 yu0419t@gmail.com）。宛先を変えるときや作り直すときのために、手順を残しておきます。

気象庁のデータの取得が3回続けて失敗すると、サーバーのログに `JMA_NOWCAST_FAILING` という文字が出ます。ひまわりとアメダスが取れないときは `HIMAWARI_FAILING`、`AMEDAS_FAILING` が出ます（このときはナウキャストだけで動き続けます）。それをメールで受け取る設定です。

1. https://console.cloud.google.com/logs/query?project=thunder-cloud-app-292e6 を開く（ログ エクスプローラ）。
2. 検索の欄に `"JMA_NOWCAST_FAILING" OR "HIMAWARI_FAILING" OR "AMEDAS_FAILING"` と入れて「クエリを実行」を押す（いまは何も出なくてよい）。
3. 「アラートを作成」（Create alert）を押す。
   - 名前: 「気象庁のデータが取れない」
   - 通知の間隔（Time between notifications）: 1時間くらい
   - 通知チャンネル: 「通知チャンネルを管理」からメールを足し、自分のメールアドレスを入れて選ぶ。
4. 保存する。

費用: ログに基づくアラートは、作れる数や通知の数に無料の範囲がありますが、Google Cloud の料金は変わることがあります。作る画面に料金の説明が出たら、保存する前に確かめてください（費用がかかるなら、作らずに Claude に相談してください）。
