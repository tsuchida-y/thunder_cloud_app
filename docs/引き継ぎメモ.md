## 3. よく使うこと

### iPhone に入れる（Mac から直接、リリース版）

```
flutter run --release -d 00008110-000544113E05401E --dart-define-from-file=config/revenuecat.json
```

- config/revenuecat.json は RevenueCat の公開用キー（appl_…、公開してよい）。これがないと Plus の画面が「いまは購入の準備中です。」になる。
- 無線のときに「Could not run … Error running application」で止まることがある。ビルドはできているので、`xcrun devicectl device install app --device 00008110-000544113E05401E build/ios/iphoneos/Runner.app` で入れて、tsuchida さんに開いてもらう。
- アプリを消して入れ直すと、通知の宛先（FCM トークン）が変わる。試しの通知を送る前に、members の fcmTokenUpdatedAt が入れ直したあとの時刻になっているか確かめる（古い宛先に送って届かないことが2回あった）。

### デバッグ版の切り替え（デバッグ版だけで効く）

- `--dart-define=FORCE_DAYTIME=true` 夜でも昼として扱う
- `--dart-define=FAKE_HEADING=100` 方位センサーのないシミュレータで向きを決める
- `--dart-define=START_SCREEN=plus` 起動してすぐ Plus の画面（審査用のスクリーンショット）
- `--dart-define=START_SCREEN=loading` 読み込み画面を出し続ける
- シミュレータのスクリーンショット: `xcrun simctl io 761730A9-B34A-4E8F-8434-ED140502AE9C screenshot 保存先.png`

### 試しの通知

`functions` フォルダで `npm run test:notify`（岩手山に雲があることにする）。`-- 39.70 141.15` で場所、`-- --uid=…` で宛先を選ぶ。宛先が2人以上いると止まる。通知の回数の記録には残らない。

### TestFlight に上げる

1. pubspec.yaml の version のビルド番号を上げる（いま 2.0.0+7 まで上げた。次は +8）。
2. `flutter build ipa --release --dart-define-from-file=config/revenuecat.json --export-options-plist=ios/ExportOptions.plist`
3. ios/ExportOptions.plist の設定で、作ったらそのまま App Store Connect にアップロードされる（Xcode にサインインしている Apple ID を使う）。
4. いまの Flutter では、アップロードのあとに「build/ios/ipa が見つからない」と言って落ちる（終了コード 1）。アップロードは済んでいる。`$TMPDIR/Runner_（日時）.xcdistributionlogs/ContentDelivery.log` に「UPLOAD SUCCEEDED」があれば成功。
5. TestFlight に出るまで 10〜30分。内部テストのグループに、テスター（tsuchida さん）とビルドの両方を入れないと、iPhone の TestFlight に出てこない（2026-10-29 にテスターを入れ忘れていた）。

## 4. つまずいたところ（同じことが起きたら）

- **iOS 27 と UIScene:** プラグインの登録が起動より後になる。通知を押したことが firebase_messaging に届かないので、AppDelegate.swift が押された通知のデータを持っておき、アプリがチャンネル `thunder_cloud/notification_tap` で取りに行く形にした。ウィジェットのタップ（URL）が届くかは、まだ確かめていない。
- **RevenueCat の権利の ID:** RevenueCat の権利の Identifier が `plus` と違っていて、買っても Plus にならなかった。revenuecatWebhook は、読み飛ばしたときに付いていた権利の ID をログに出すようにしてある。アプリは RevenueCat の権利も見るので、サーバーに届く前でも Plus として使える。
- **値段がドルで出る:** ストアの値段をそのまま出しているので、Apple ID（やサンドボックスのアカウント）の国がアメリカならドルになる。tsuchida さんの Apple ID はそうなっている。アプリの不具合ではない。つぎめも（別のアプリ）は値段を「円」と決め打ちしていたので気づかなかった。
- **サンドボックスのテスト用アカウント:** ふだんの Apple ID のメールアドレスでは作れない。作るなら `yu0419t+jp@gmail.com` のような別名で。TestFlight の版なら要らない。
- **本番の Firestore の書き換え:** Claude Code の安全の仕組みに止められることがある。tsuchida さんが会話で了承すると通る。止められたら、別のやり方で回り込まない。
- **Xcode のウィジェットのターゲット:** 新しい Xcode は、ターゲットのフォルダ（ios/CloudWidget）の中のファイルを自動でターゲットに入れる。ひな形を消すとリポジトリのファイルまで消えるので、消えたら `git restore` で戻せばよい。App Groups は Xcode の画面で名前を入れられなかったので、entitlements のファイル（ios/Runner/Runner.entitlements、ios/CloudWidgetExtension.entitlements）に直接書いた。「Embed Foundation Extensions」を「Thin Binary」より前にしておく（Cycle inside Runner のエラーを防ぐ）。
- **デバッグ版を iPhone で動かす:** iproxy が Intel 用なので Rosetta が要る（入れてある）。iOS 27 では Mac とつながるまで数分かかることがある。
- **Notion:** 権限のモードによって、読めないことがある。そのときはリポジトリの資料で進める。
