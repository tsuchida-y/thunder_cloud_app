## 1. 雲の場所をどのデータで知るか

### 決定

気象庁ホームページの「高解像度降水ナウキャスト」と「雷ナウキャスト」を使い、強い雨の塊や雷が出ている場所を「入道雲がある場所」とみなします。画面には「出典：気象庁ホームページ（加工して作成）」と書きます。

今使っている Open-Meteo の予報データ (CAPEなど) で「入道雲ができそう」と独自に判定する仕組みはやめます。

### 理由

気象庁ホームページの内容は「公共データ利用規約 第1.0版」で提供されていて、規約に「商用利用も可能です」と書かれています。出典を書けば、有料アプリでも無料で使えます。

一方で、自分で計算して「何時ごろ、どこで入道雲ができそう」と一般の人に知らせることは、気象業務法の「予報業務」にあたり、気象庁の許可と気象予報士が必要になる可能性が高いです。気象庁のQ&Aには「どのような予測の方法であっても、予報業務を行うには予報業務許可が必要」とあり、無料か有料かの区別もありません。今のアプリの「入道雲の可能性50%」の通知もこれに近いので、早めに切り替えるのが安全です。気象庁が出した予報 (雷注意報や雷ナウキャストの1時間先の予測) を紹介するだけなら許可はいりません。

もう1つの理由として、Open-Meteo の無料APIは商用利用が禁止されています。収益化するなら有料プランが必要になりますが、上の切り替えをすれば Open-Meteo 自体が不要になります。

### この決定に合わせて変えたこと

雲がないときの画面の「きょう現れそうな時間」のグラフ (独自の予想) をやめ、気象庁の雷注意報と雷ナウキャストを紹介する欄に変えました。ホームの「30分後に出そう」は、気象庁の雷ナウキャストや降水ナウキャストの1時間先の予測をもとにする前提で「（気象庁の予測）」と書き添えました。

### 注意点と、あとでやること

気象庁ホームページのデータは、アプリから使うための公式な窓口ではなく、URLや形式が予告なく変わることがあります。取得部分はサーバー (Cloud Functions) にまとめ、壊れたらすぐ気づけるようにしておきます。アクセスは5分おき程度に抑え、全ユーザー分をサーバーで1回取得して使い回します。

安定した公式データ (GRIB2形式) は気象業務支援センターから有料で受け取れますが、料金は公開されていないので、収益が出てから見積もりを取ります。

ひまわり衛星の雲の高さのデータは、扱いが難しいので最初は使いません。

「30分後に出そう」の予告が「予報の紹介」の範囲に収まるかは判断が分かれる可能性があるので、リリース前に気象庁 情報基盤部 情報利用推進課に一度確認するのがおすすめです。

## 2. 最初の許可画面と、困ったときの画面

キャンバスの下の段に4画面を追加しました。

はじめての起動では、アプリが何をするかを一文で伝え、位置情報 (常に許可) と通知が必要な理由をそれぞれ一行で説明してから、まとめて許可をお願いします。断った人のために「あとで設定する」も置きます。

夜は、時刻を決め打ちにせず、日没から翌朝の日の出までを「見張りはお休み中」とします。暗くて入道雲が見えないためです。お休み中は、次に再開する時刻と、その日に見えた入道雲の記録を出します。

通信できないときは、最後に受け取った情報と時刻を出し、「いまも見えるかは分かりません」と添えて、もう一度読み込むボタンを置きます。

許可がないときは、位置情報と通知のそれぞれについて、オフになっていることと直し方を出します。位置情報を許可したくない人のために、場所を手で登録する道も残します。

## 3. 通知のルール

1つの雲には1回だけ通知します。雲が移動したり大きくなったりしても、同じ雲として追いかけて、もう一度は鳴らしません。一度消えた雲の場所に60分以上たってから新しい雲が出たときは、別の雲として扱います。

予告 (「出そうです」) を送った雲が実際に見えたときは、新しい通知を足さずに、同じ通知を「現れました」に書き換えます。

通知と通知のあいだは最低30分あけます。1日の上限は3回にします。

日没から日の出までは通知しません。通知しない時間は設定で変えられます。

アプリを開いて10分以内に見ている人には通知しません (もう画面で見ているため)。

通知には「見えた」「見えなかった」のボタンを付け、押された結果を判定の改善に使います。

## 4. 有料プラン

### 決定

無料プランと「入道雲サーチ Plus」の2つにします。広告は出しません。

無料プランでできること: 見えている入道雲の通知 (30kmまで)、ホームのレーダー、方角ガイド、写真を撮って保存すること。

Plus でできること: 30分前の予告通知、通知する範囲を見える限り (約90km) まで広げる、よく行く場所を3か所まで登録する、ホーム画面のウィジェット、撮った写真に方角と距離を入れてSNSに共有、今年見えた入道雲の記録。

値段は月額200円、年額1,200円にします。

### 理由

開いて数秒で閉じる使い方なので、広告は見られる時間が短く収益になりにくいです。また広告を入れると、大事にしたい空の雰囲気が崩れます。

入道雲が出るのはおもに6月から9月です。月額だと夏だけ入って秋に解約されやすいので、年額を月額の半分の値段 (月あたり100円) にして、梅雨前に年額をおすすめする作戦にします。無料で7日間 Plus を試せるようにし、予告通知の便利さを体験してもらいます。

無料プランでも「見えたら知らせる」と「方角が分かる」という、アプリの一番大事な役割は使えるようにしておき、満足してもらったうえで、もっと遠くまで・もっと早く知りたい人に Plus をすすめます。

## 5. 作り直しの進め方 (2026-10-20)

今の Open-Meteo を使う Cloud Functions は、v2.0 を公開するまで本番で動かし続けます。今のアプリ (1.0.4) はこのデータを読んで動いているので、先に止めると公開までのあいだ誰にも通知が届かなくなるためです。コードはブランチで消し、新しい気象庁の仕組みは別の関数として横に並べて試し、v2.0 の公開と同時に古い関数を止めます。今のアプリは無料なので、それまでは Open-Meteo の非商用の条件に収まります。

users のキーは、FCM トークンから端末の ID (Firebase の匿名ログインを入れる) に移します。トークンが変わるたびに古いデータが残る問題と、セキュリティルールがアプリと合っていない問題をまとめて直すためです。既存データの移し方は、作業の前に説明して確認を取ります。

ウィジェットには雷注意報を出しません。ホームと同じく、気象庁の注意報は扱いません。

## 次にやること

1. 気象庁ホームページのナウキャストのデータを Cloud Functions から取得して、雲の塊の位置を出す試作を作る
2. 予告通知の扱いを気象庁 情報利用推進課に確認する
3. 新しい画面をアプリに組み込む (Flutter)
4. アプリ内課金 (Plus) を組み込み、2027年4月までに公開する (プロジェクトの「半年で収益を受け取る」目標に合わせ、梅雨入り前に年額をすすめる)
