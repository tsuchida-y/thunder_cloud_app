# 検知の精度を上げるデータの比較

2026-10-22 にまとめました。入道雲を見つけるしくみを見直し、ナウキャストのほかにどのデータを足すかを比べた記録です。結論として、気象庁ホームページの「ひまわり」の赤外画像と「アメダス」を足しました。

## 1. 何を見つけたいか

このアプリで知らせたいのは、いまいる場所から見上げると、晴れた空にそびえて見える入道雲です。雲の下にいるときや、空が一面の雲で覆われているときは、入道雲の形が見えません。強い雨が降っているだけでは足りず、「離れた所に背の高い雲が立っていて、自分の場所からその姿が見える」ことが大事です。

## 2. もとのしくみで足りなかったこと

もとのしくみは、高解像度降水ナウキャストと雷ナウキャストから、1時間に30mm以上の雨か雷の活動度2以上の場所がつながった塊を入道雲とみなしていました。2026-10-22 17:00 の実データで動かすと、沖縄のまわりで53個の塊が見つかりました。いちばん大きい塊は約1,440km² で、多くの塊は雷の活動度が0でした。広い雨を入道雲として数えていたことになります。

足りなかった点は次の5つです。

1. 台風や前線の広い雨も入道雲として知らせる。空は一面の雲で、入道雲の形は見えない。
2. 真上や、すぐ近くの雲も知らせる。距離を塊の中心で測るので、大きい塊だと雨の中にいても「15km 先」になる。
3. 育っている途中の入道雲は、まだ強い雨が降らないので見つからない（ナウキャストの性質上、なくせない）。
4. z6 のタイル（1ピクセル約2km）では、近くの雲が1つにまとまり、中心が雲と雲の間の空になることがある。同じ場所を z8 で見ると70個の塊が、z6 では38個にまとまり、面積は約1.6倍に出た。
5. 雲のてっぺんを12km と決め打ちしている。山や、かすみで見えない雲も知らせる。

なお、最初に z4 で日本全体を見るときに小さな雲を見落としていないかも確かめました。z6 の全部のタイルで調べた結果と同じで、見落としは0件でした。z4 のタイルは、広い範囲のいちばん強い雨を出していて、z6 の雨のある約94,000ピクセルすべてで、z4 にも同じかそれより強い雨がありました。

## 3. 先に入れた2つ（ナウキャストだけでできること）

ほかのデータを足す前に、次の2つを入れました（2026-10-22、デプロイ済み）。

1. 見張る場所で1時間1mm以上の雨が降っていたら、その場所では知らせない。
2. 雲のふち（塊の端）が10kmより近い雲は知らせない。雲が離れて10kmを超えたら、そのとき知らせる。

17:00 の沖縄のデータでは、以前なら那覇・名護・宮古島・久米島に「入道雲が現れました」が届いていましたが、どこも雨が降っているので送らなくなりました。

## 4. 比べた案（18個）

規約、費用、効き目、手間の4つで比べました。

### 使えるもの（無料で、規約上も問題がない）

気象庁ホームページのデータは、出典を書き、加工したことを書けば、商用でも使えます（気象庁ホームページの利用規約）。

1. ひまわりの赤外画像（気象庁ホームページ、2.5分ごと）。雲のてっぺんの温度が分かり、背の高い積乱雲か、低い雲の雨かを見分けられる。てっぺんの高さも見積もれる。効き目がいちばん大きい。ただし白黒の JPEG で、明るさと温度の対応表が公開されていないので、自分で対応を見積もる必要がある。
2. ひまわりの雲頂強調画像（同じ所）。てっぺんが高い所に色が付く。1の確かめに使える。
3. ひまわりの可視画像（同じ所）。昼だけ使える。雲までの間が晴れているかが分かるが、雲の厚さと高さは赤外のほうが分かりやすい。
4. アメダスの日照時間（約840地点、10分ごと）。近くで日が差していれば、空は一面の曇りではない。雨のない曇り空を外せる。
5. アメダスの視程と天気（約150の気象台など）。視程は20kmまでしか出ないが、20kmより短いときは、かすんで遠くが見えないと分かる。
6. 国土地理院の標高タイル。山に隠れて見えないかを計算できる。出典を書けば商用でも使える。
7. いまのナウキャストで、雲までの間の雨を見る（追加のデータなし）。間に強い雨があれば、雲はその陰に隠れる。

### 条件つき

8. ひまわりの元のデータを気象業務支援センターから買う。精度は高いが有料で、いまの売上の見込みに対して高い。
9. レーダーのエコー頂高度（雲の背の高さ）。気象庁ホームページでは公開されていないようで、手に入れるには契約が要る。
10. 「見えた」の答えを近くの人どうしで使う。規約の問題はないが、利用者が多くないと効かない。

### 使えない、または使わないほうがよいもの

11. JAXA ひまわりモニタ（P-Tree）の雲頂高度。いちばん欲しいデータだが、研究・教育など非営利に限られ、商用は不可。
12. AWS にある NOAA のひまわりデータ。気象庁がひまわりのデータの商用を原則認めていないと読めるので、使うなら問い合わせが要る。
13. Blitzortung の雷のデータ。商用は禁止。
14. フランクリン・ジャパンの雷データ、ウェザーニューズ、日本気象協会の API。有料で高い。
15. 国土交通省の XRAIN。研究向けか有料。
16. Open-Meteo、Tomorrow.io、OpenWeather の CAPE などの予報。Open-Meteo は無料版の商用が禁止で、どれも予報を使うことになり、予報業務の恐れがある。
17. 気象庁の1時間先の予測で先に知らせる。v2.0 ではやらないと決めている（docs/将来の検討.md）。
18. 写真やライブカメラを AI で見分ける。写真の機能は v2.0 で外している。

## 5. ひまわりの赤外画像とアメダスを選んだ理由

1. 効き目が大きい。ナウキャストは「強い雨がある所」しか分からないが、入道雲が見えるかは「雲が背の高い雲か」と「自分の場所の空が開けているか」で決まる。前者をひまわり、後者をアメダスで補える。
2. 法律と規約の面で安全。どちらも気象庁ホームページのデータで、出典を書けば商用で使える。どちらも予想ではなく、いまの観測を読み取るだけなので、予報業務にあたる恐れは小さい。
3. 費用がかからない。気象庁へのアクセスは5分に1回のまとめ取りのまま、1回あたり24回前後から33回前後に増えるだけ（アメダス2回、ひまわりの時刻1回、ひまわりのタイル数枚）。
4. 今のしくみに足しやすい。ひまわりのタイルはナウキャストと同じタイルの並びなので、雲の塊の場所でそのまま読める。

標高タイル（案6）と雲までの間の雨（案7）も効きますが、効く場面がより限られるので、あとで「見えなかった」の答えが多いときに検討します。可視画像（案3）は夜明けや夕方に使えず、赤外画像と役目が重なるので見送りました。

## 6. 入れたしくみ

雲の場所は今までどおりナウキャストで決めます。ひまわりとアメダスは「見えるかどうか」の確かめと、てっぺんの高さにだけ使います。

1. 背の高い雲だけを入道雲にする（ひまわり）。強い雨か雷の塊のまわりで、いちばん冷たい雲のてっぺんの温度を調べ、-20℃ より冷たい塊だけを入道雲とします。夏ならおよそ高さ7〜8km より上です。衛星から斜めに見るので、背の高い雲は北へ10km ほどずれて写ります。そのずれと時刻のずれの分、塊のまわり約13km まで見ます。
2. てっぺんの高さを見積もる（ひまわり＋アメダス）。てっぺんの温度と、雲の近くのアメダスの気温の差を、1km で 6.5℃ 下がるとして高さに直し、6〜16km に収めます。見上げる高さ（こぶしの数）は、この高さで計算します。分からないときは今までどおり12km です。
3. 一面の曇りの場所では知らせない（アメダスの日照時間）。見張る場所から20km 以内のアメダスが、どこも前の1時間ずっと日が差していなければ、一面の曇りとします。1地点だけだと、入道雲そのものの影に入っただけのこともあるので、近くの地点をすべて見ます。太陽が15°より低いと、晴れていても日照なしになるので、その時間はこの判定をしません。
4. かすんで見えない遠くの雲は知らせない（アメダスの視程）。見張る場所から40km 以内のいちばん近い地点の視程が20km より短いときは、それより遠い雲を知らせません。

ひまわりかアメダスが取れないときは、ナウキャストだけで今までどおり続けます。3回続けて取れないと、Cloud Logging に `HIMAWARI_FAILING`、`AMEDAS_FAILING` のエラーを出します。

コードは functions/modules/jma/himawari_client.js、amedas_client.js、sky_observations.js、数字は functions/constants.js の HIMAWARI と AMEDAS にあります。

## 7. 赤外画像の明るさを温度に直す式の見積もり

気象庁は、ホームページの白黒の赤外画像の明るさと温度の対応表を公開していません。そこで、2つの目印から直線の式を見積もりました。

1. 晴れたアメダス地点。2026-10-22 12:00 に10分間ずっと日が差していた361地点で、画像の明るさと気温を比べました。気温が高いほど暗く、20〜24℃ の地点で明るさは約38でした。昼の地面は気温より少し熱いので、約+25℃ で明るさ約38としました。
2. 雲頂強調画像の色。同じ時刻の雲頂強調画像で色が付いている所の明るさを調べると、色は明るさ約145から付きはじめ、赤は約200〜235でした。解説記事で「赤は約200K（約-73℃）」とされているので、明るさ約225 で約-73℃ としました。

この2点から、温度（℃）≒ 45 − 明るさ ÷ 1.9 としました。この式だと、色が付きはじめる明るさ145は約-31℃ になります。

誤差は数℃あると考えています。入道雲とする -20℃ の線引きと、てっぺんの高さの見積もりは、夏に集まる「見えた」「見えなかった」の答えで調整します。

## 8. 実データで確かめたこと（2026-10-22）

17:30 の沖縄の63個の塊は、どれもてっぺんが約-60〜-80℃、高さ約13〜16km と出て、ひまわりで外された塊はありませんでした。熱帯の大きな雨雲は対流圏の上の端（約16km）まで届くので、もっともな値です。この日の沖縄は空一面が冷たい雲に覆われていて、通知を止めたのはひまわりではなく、先に入れた「雨の中では知らせない」でした。昼なら「一面の曇り」の判定も効きます。ひまわりは、暖かい雲から降る強い雨（梅雨や夏の海の上で多い）を外すのと、見上げる高さを本当の高さに近づけるのに効きます。

## 9. まだ分からないこと、これから調整すること

- -20℃ の線引き、6.5℃/km、日照の20km と1時間、視程の使い方は、どれも最初の目安です。夏の「見えた」「見えなかった」で調整します。
- 赤外画像の式は見積もりです。気象庁が対応表を出したら、それに合わせます。
- 雲のてっぺんの温度は塊のまわり約13km でいちばん冷たい所なので、すぐ隣に別の背の高い雲があると、背の低い塊も入道雲になることがあります。
- 背の高い雲が空一面を覆っている広い雨（台風など）は、ひまわりだけでは見分けられません。雨と日照の判定で外します。
- 気象庁ホームページはアプリ向けの公式な窓口ではないので、URL や形式が変わることがあります。そのときはエラーのログで気づき、取得の部分を直します。
