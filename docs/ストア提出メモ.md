### 説明文

あなたの場所から見える空に入道雲が現れたら、どの方角に、どのくらいの高さで見えるかをお知らせします。

ホームを開けば、見えている入道雲の方角と距離がひとことで分かります。「雲の方角を調べる」でスマホを向ければ、「右へ35°」のように案内し、向きが合うと軽く振動して知らせます。見上げる高さは、腕を伸ばした「こぶしいくつ分」で表します。

通知は1つの雲につき1回、30分以上あけて1日3回まで。空が暗くなってから明るくなるまでは、入道雲が見えないので通知しません。

【Plus（有料）】
・見張る範囲を90kmまで広げる（無料は30km）
・いまいる場所に加えて、家や学校など3か所まで見張る
・ホーム画面のウィジェット
月額200円、年額1,200円。はじめての方は7日間無料で試せます。期間が終わる24時間前までに解約しないと自動で更新されます。解約は App Store / Google Play の設定からいつでもできます。

【データについて】
雲の場所は、気象庁ホームページの高解像度降水ナウキャストと雷ナウキャストをもとに、強い雨や雷のある場所をまとめて作っています。雲の背の高さはひまわりの赤外画像から、空のようすはアメダスの観測から見積もっています。本アプリの表示は気象庁が発表したものではありません。
出典：気象庁ホームページ（加工して作成）

## 2. App Store の審査へのメモ（App Review Information の Notes、下書き）

- 位置情報の「常に」について: 本アプリは最初に「使用中」の位置情報だけをお願いします。「常に」は、最初の入道雲の通知が届いたあとに、移動先の空も見張る目的を説明する画面を1回だけ出し、利用者が選んだときにだけお願いします。「常に」の場合は、OS の大きな移動の検知（significant location change）だけを使い、約1km以上移動したときに場所を約1kmの細かさで更新します。常時の GPS 追跡はしません。
- 通知について: 利用者の場所から見える範囲に入道雲（強い雨か雷のある場所）があるときだけ送ります。空が暗いあいだ（日の入りの約30分後から日の出の約30分前まで）は送りません。
- データについて: 気象庁ホームページの公開データ（公共データ利用規約に基づき商用利用可）を運営者のサーバーで5分ごとに取得し、加工しています。予報（いつどこで発生するかの予想）は行いません。
- 定期購入について: Plus の購入画面に、無料期間のあとの値段と自動更新を、購入ボタンのすぐそばに出しています。利用規約とプライバシーポリシーへのリンク、購入の復元も同じ画面にあります。
- ログインについて: アカウントの作成はありません（Firebase の匿名ログインのみ）。

## 4. ベータ配布の手順

前提: RevenueCat の公開用の API キー、iOS のウィジェットのターゲット、App Group ができていること（残りの作業の「2. お願いしたい作業」）。

### iOS（TestFlight）

1. `flutter build ipa --release --dart-define=REVENUECAT_IOS_KEY=（iOS の公開用キー）`
2. できた build/ios/ipa の .ipa を Transporter か Xcode の Organizer で App Store Connect に上げる。
3. TestFlight の「内部テスト」に tsuchida さんの Apple ID を入れて試す。

### Android（内部テスト）

1. `flutter build appbundle --release --dart-define=REVENUECAT_ANDROID_KEY=（Android の公開用キー）`
2. build/app/outputs/bundle/release の .aab を Play Console の「内部テスト」に上げる。
3. テスターに tsuchida さんの Google アカウントを入れて試す。

バージョンは pubspec.yaml の `version: 2.0.0+6`。上げ直すたびに + のあとの数字を1つ増やす。

## 5. 公開するときの順番

今のアプリ（1.0.4）を使っている人に迷惑がかからない順番にする。

1. Cloud Functions をデプロイする（関数名を指定する）: updateNowcastClouds, cleanupOldClouds, revenuecatWebhook, cleanupInactiveMembers。Firestore のルールもデプロイする。
2. 審査に出す。通ったら公開する。
3. 公開と同じ日に、feature/new-ui を main に入れる。GitHub Pages の利用規約と新しいプライバシーポリシーがここで公開される（早く入れると、1.0.4 の利用者に v2.0 の内容のポリシーが見えてしまう）。
4. 公開と同じ日に、v1 の写真のデータ（photos・likes・comments・downloads と Storage）と cleanupExpiredPhotos を消す（2026-10-21 了承。新しいプライバシーポリシーとストアの文に「削除しました」と書いているため）。消す直前に対象と件数を見せる。
5. 多くの人が 2.0 に上げたのを見てから、v1 の Cloud Functions（Open-Meteo）を止めて消し、Firestore のルールの v1 の部分を締め直し、Google マップの API キーを無効にする（残りの作業の「4. 公開するときにやること」）。
