## 予告通知（「入道雲が出そうです」）

2026-10-22 に、v2.0 では作らないと決めました（tsuchida さん）。

### どんな機能だったか

- Plus の機能として計画していた。
- 気象庁の高解像度降水ナウキャスト・雷ナウキャストの「1時間先までの予測」を使い、30分以内に利用者の見える範囲に入りそうな雲があるときに先に知らせる。
- 通知の文の例: 「西の空に、入道雲が出そうです」「気象庁の予測では30分後くらい。約85km先なので、見えるかもしれません。」
- 予告した雲が実際に見えたら、新しい通知を足さずに、同じ通知を「現れました」に書き換える（サーバーは雲の ID で通知をまとめる作りになっているので、そのまま使える）。
- 設定に「出そうなときも先に知らせる」（Plus）のスイッチ、ホームの雲の一覧に「30分後に出そう」、ウィジェットに「西にも出そう（30分後）」を出す予定だった。

### やめた理由

気象業務法では、天気の予想を人に知らせる「予報業務」には気象庁の許可と気象予報士が要る。気象庁の予測をそのまま紹介するだけなら許可は要らないが、この機能は利用者ごとに「あなたから見て30分後くらいに入りそう」と加工して知らせるので、「予測の紹介」か「独自の予報」かの判断が分かれるおそれがある。確かめるには気象庁（情報基盤部 情報利用推進課）への問い合わせが要る。v2.0 では、この問い合わせをせずに、予告通知そのものを作らないことにした。

### もう一度考えるときにやること

1. 気象庁 情報基盤部 情報利用推進課に、予報業務許可なしで出せるかを問い合わせる（アプリの内容、使うデータ、加工のしかた、通知の文の例を送る。送るのは運営者の tsuchida さん）。
2. 出してよいと分かったら、サーバー（functions）でナウキャストの予測の時刻のタイルも読み、30分以内に範囲に入る雲を探して送る。今の通知のルール（1つの雲に1回、30分以上あける、1日3回まで、夜は送らない）とどう数えるかを決める。
3. アプリの設定、Plus の画面、ホーム、ウィジェットに、上の表示を戻す。v2.0 のデザインの HTML からは消してあるので、git の履歴（2026-10-21 までの docs/design/）を見る。

## ウィジェットの中身を、アプリを閉じたままでも新しくする

いまのウィジェットは、アプリを開いたとき（と Android で通知を受けたとき）にしか新しくならないので、「15:21 時点」と時刻を出している。閉じたままでも新しくするには、サーバーから見えない通知（サイレントプッシュ）を送ってウィジェットを描き直す仕組みが要る。通知の回数や電池への影響を見ながら、公開後に考える。
